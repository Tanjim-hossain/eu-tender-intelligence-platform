# TenderGraph v1 — frozen final scope

Owner decision: 24 November 2026. No further feature expansion beyond the seven
agreed phases. No paid service, domain, hosting, provider subscription, or billing
activation until the owner explicitly approves after the one-to-two-month break.

| Phase | Acceptance gate |
| --- | --- |
| 1. Historical procurement intelligence | Bounded indexed buyer history, result notices, currency-separated estimated values, explicit historical supplier evidence when available. |
| 2. Feedback-driven ranking | Account-scoped conservative feedback ranking; preserve original fit score; no supervised model claims without labeled usage data. |
| 3. Final UI/UX | Existing workspace polish, clear onboarding, mobile layout, filtering, decision export, empty/error states. |
| 4. Production hardening | Local automated security/regression checks, deployment guardrails, documented backup/restore and operational gates. Live infrastructure/security verification remains mandatory. |
| 5. External beta | Real consenting SME testers complete the workflow and report results; no fabricated participants or feedback. |
| 6. Public deployment | Owner-approved infrastructure, TLS, private database, verified refresh and recovery, public registration, release documentation. |
| 7. Monetization | Owner-approved pricing, payment provider, legal/tax/privacy review, test-mode subscription lifecycle, then live payments and first paying customer. |

No autonomous bid writing, new scraping targets, additional ML architecture,
new services, team collaboration, or unrelated enhancements are in scope.
Bug fixes and release blockers within the seven phases are allowed.

## Free-first completion boundary

A feature freeze is not the same as a production release. No external users,
public deployment, payment processing or commercial success may be marked done
without real evidence. The owner can pause development with a tested release
candidate and a precise launch checklist, then resume only the remaining gates.
